## Эпизод 1. Каркас проекта: CMake, структура каталогов, обвязка тестов

**Запрос.** Прочитать условия работ в `OOP_Labs`, разобрать датасет и собрать
инфраструктуру проекта: структуру каталогов на весь семестр, CMake с
разделением на библиотеку ядра, приложения и тесты, санитайзеры в Debug,
регистрацию тестов в CTest, `.gitignore`, `AGENTS.md`, скелет README.

**Что получено.**

- `CMakeLists.txt` в корне: C++20, `-Wall -Wextra -Wpedantic`, интерфейсная цель
  `oop_project_options` с общими флагами, ASan и UBSan в конфигурации Debug
  через generator expression `$<$<CONFIG:Debug>:...>`, опция
  `OOP_ENABLE_SANITIZERS` для их отключения.
- `core/CMakeLists.txt`: библиотека ядра, список исходников через
  `file(GLOB_RECURSE ... CONFIGURE_DEPENDS)`.
- `apps/lab1/`, `tests/`: приложение первой работы и каталог тестов с функцией
  `oop_add_test`, которая создаёт цель и регистрирует её в CTest.
- `tests/testing.hpp`: макросы `CHECK`, `CHECK_NEAR`, `CHECK_THROWS_AS`, счётчик
  провалов и `summary()`, возвращающий ненулевой код при ошибке. Отдельный
  фреймворк не используется — условие его не требует.
- `.gitignore`, `AGENTS.md`, скелет `README.md` с описанием датасета.

**Ошибка агента.** Первая версия `core/CMakeLists.txt` не сработала. Пока
`core/src/` пуст, `add_library(oop_core STATIC ${SOURCES})` с пустым списком
падает на этапе генерации:

```text
CMake Error at core/CMakeLists.txt:12 (add_library):
  No SOURCES given to target: oop_core
```

Агент рассчитывал, что достаточно задать `LINKER_LANGUAGE CXX` — это лечит
другую ошибку, определение языка цели, но не отсутствие исходников как таковое.
Исправлено ветвлением: пока `.cpp` нет, цель создаётся как `INTERFACE`
(header-only) и раздаёт только каталог заголовков; как только в `src/` появляется
первый файл, она становится `STATIC`. Область видимости требований
(`PUBLIC`/`INTERFACE`) при этом тоже меняется, поэтому она вынесена в
переменную `OOP_CORE_SCOPE`.
