## Эпизод 3. Разбор ошибок сборки: `main` в библиотеке, ODR, include guard

**Запрос.** «Я создал пока что базовую часть, она же соберётся?» — проверить
первую версию `dataset.hpp` и `dataset.cpp`.

**Что получено.** Проект собирался, но по случайности. Агент нашёл три места и
воспроизвёл каждое отдельной командой, а не ограничился описанием.

1. **Нет `#pragma once`.** Пока заголовок включён из одного файла — тихо. При
   включении в две единицы трансляции:

   ```text
   error: redefinition of 'struct NumericColumn'
   ```

2. **Глобальная переменная `fs::path p` определена в заголовке.** Каждый `.cpp`
   получал свою копию, и компоновщик ругался:

   ```text
   ld: c.o:(.bss+0x0): повторное определение «p[abi:cxx11]»;
       b.o:(.bss+0x0): здесь первое определение
   ```

   Компилятор при этом молчит — ошибка появляется только на линковке. Правило:
   в заголовке можно объявлять (`extern`), определять нельзя, кроме `inline`,
   `constexpr`, шаблонов и членов классов.

3. **`main()` лежал в `core/src/dataset.cpp`, то есть внутри библиотеки ядра.**
   `nm` показывал в `liboop_core.a` ровно один символ — `T main`. Приложение
   собиралось только потому, что из `dataset.o` ничего не требовалось:
   статическая библиотека подтягивает объектный файл лишь тогда, когда из него
   нужен хотя бы один символ. Агент смоделировал ситуацию, добавив в библиотеку
   функцию и вызвав её из приложения:

   ```text
   ld: libcore.a(ds.o): в функции «main»:
       повторное определение «main»; app.o: здесь первое определение
   ```

   То есть сборка сломалась бы ровно в тот момент, когда загрузчик начали бы
   использовать по назначению.

**Что принято, изменено, отклонено.**

Приняты все три замечания. `main` перенесён в `apps/lab1/main.cpp`, путь к
файлу убран из ядра в приложение (ядро не должно знать, откуда взялись данные),

## Эпизод 5. Отладчик VS Code и особенности gdb на типах из `dataset.hpp`

**Запрос.** «Хотелось бы подключить дебаггер VS Code, чтобы внутри программы
следить за значениями переменных.»

**Что получено.** `.vscode/launch.json` с двумя конфигурациями (приложение и
тесты) и `.vscode/tasks.json` с задачами сборки и прогона тестов. Существенные
настройки:

- `cwd` — корень репозитория, иначе относительный путь `data/cirrhosis.csv` под
  отладчиком указывал бы не туда, куда при запуске из терминала;
- `preLaunchTask` — пересборка перед стартом, чтобы не отлаживать старый
  бинарник;
- `ASAN_OPTIONS=abort_on_error=1` — без него AddressSanitizer печатает отчёт и
  завершает процесс сам, отладчик до места ошибки не доходит и стек посмотреть
  нельзя;
- `-enable-pretty-printing` — разбор контейнеров STL.

**Три особенности, выясненные на практике.**

1. **Точка останова на закрывающей `}` функции показывает мусор.** При первой
   проверке агент поставил её именно туда и получил пустой `cat` и `col` без
   значения. Причина: на `}` уже работают деструкторы, объекты разрушаются в
   обратном порядке объявления. Уцелел только `num`, объявленный первым. Точку
   останова надо ставить на последнюю содержательную строку.

2. **`std::get<CategoricalColumn>(col)` в отладчике вызвать нельзя** —
   `No symbol "get<CategoricalColumn>"`. gdb не вызывает шаблонные функции. Это
   не мешает: `variant` и так печатается вместе с номером альтернативы.

3. **`std::ifstream` показывается как `<incomplete type>`** — у потоков нет
   отладочной информации в системной библиотеке. Состояние потока приходится
   смотреть по ветке исполнения или через отдельную переменную `bool`.

**Как выглядят типы из `dataset.hpp` под отладчиком.**

```text
num.values = std::vector of length 4, capacity 4 = {
               std::optional = {[contained value] = 10},
               std::optional = {[contained value] = 15},
               std::optional [no contained value],
               std::optional = {[contained value] = 22}}

col2       = std::variant [index 1] = {{values = std::vector of length 3 = {
               std::optional = {[contained value] = "red"},
               std::optional [no contained value],
               std::optional = {[contained value] = "blue"}}}}
```

Пропуск виден как `[no contained value]`, у `variant` виден `index`: 0 —
`NumericColumn`, 1 — `CategoricalColumn`. Для отладки загрузчика этого хватает.

**Что принято, изменено, отклонено.**
