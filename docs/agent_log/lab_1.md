## Эпизод 6. Форматирование таблиц вывода: `std::format` вместо `iomanip`

**Запрос.** «Как можно сделать красивый вывод таблицы, не изощряясь?» — нужен
вывод сводки по признакам в формате из условия работы.

**Что получено.** Рекомендация использовать `std::format` (C++20) и набор
спецификаторов под задачу. Существенно, что выбор здесь не про удобство:
`iomanip` в этом проекте **не работает**.

Сравнение на одних и тех же данных:

```text
═══ std::format ═══
  #  Признак        Тип              Пропуски
  0  Age            числовой                0
  1  Drug           категориальный        106

═══ iomanip ═══
  #  ПризнакТип          Пропуски      ← колонки слиплись
  0  Age           числовой       0
```

Причина — кодировка. В UTF-8 кириллица занимает два байта на символ:

```text
"числовой".size()       = 16 байт
"категориальный".size() = 28 байт
```

`std::setw` считает байты, поэтому «Признак» для него имеет длину 14, а не 7:
ширина колонки исчерпана уже заголовком. `std::format` в GCC 14 считает ширину
в символах и выравнивает корректно.

Спецификаторы, которые закрывают требования условия: `{:<14}` и `{:>8}` —
выравнивание по краям, `{:^30}` и `{:-^30}` — по центру с заполнителем,
`{:.3f}` — дробное с фиксированной точностью, `{:<{}}` — ширина отдельным
аргументом. Гистограмма собирается как `std::string(count / scale, '#')`.

Дополнительно проверено: `std::print` из C++23 в GCC 14 работает, но требует
`-std=c++23`, а условие фиксирует C++20 — поэтому остаётся
`std::cout << std::format(...)`.

**Что принято, изменено, отклонено.**

## Эпизод 9. Цикл чтения строк CSV с `std::views::split` и проверкой согласованности

**Запрос.** «Перепиши заполнение датасета с учётом `std::views::split`,
строки 77–90.» Версия студента на `views::split` уже была написана, но не
компилировалась.

**Что было не так в исходной версии.**

1. `std::string_view(value)` из поддиапазона, который отдаёт `views::split`, в
   C++20 не компилируется: конструктор `string_view` от диапазона появился
   только в C++23.

   ```text
   error: no matching function for call to
   ‘std::basic_string_view<char>::basic_string_view(std::ranges::subrange<...>&)’
   ```

2. Один счётчик `i` использовался и как номер поля в строке файла, и как индекс
   в `raw_data`. Но в `raw_data` нет пропускаемых столбцов, поэтому после
   пропуска `ID` все значения сдвигались на один столбец, а последнее уходило
   за границы `raw_data`.
3. При несовпадении числа полей конструктор молча делал `return`, и программа
   продолжала работать с частично загруженными данными.
4. Число разделителей (знаковое, `std::ptrdiff_t`) сравнивалось с беззнаковым
   `size()` — предупреждение `-Wsign-compare`.

**Что получено.**

- Ожидаемое число полей считается один раз: столбцы датасета плюс пропускаемые.
- Номер строки ведётся как в редакторе: заголовок — строка 1.
- Проверка согласованности идёт до разбора строки: полей на одно больше, чем
  разделителей, поэтому одной проверкой ловятся и недостающие, и лишние поля, а
  хвостовое пустое поле (`a,b,`) не даёт ложной ошибки.
- При несовпадении бросается `std::runtime_error` с путём, номером строки и
  числом полей. Это временная мера до собственной иерархии исключений во второй
